# P01 local toolchain and RPC spine

This phase implements a nonfinancial instruction in clearing. It does not implement deposits, trading, balances, funding, orders or settlement. The future financial ABI is a P02 deliverable.

## Bootstrap and execution

Verified host profile: macOS 26.5.2 (25F84), arm64. Python 3.12+ and rustup are prerequisites. Bootstrap downloads official releases into ignored `.tools/`, checks their pinned SHA-256 values and does not change the machine's default tools.

```sh
python3 ops/bootstrap.py
source ops/env.sh
npm install --prefix .tools/pnpm --ignore-scripts pnpm@10.23.0
rustup toolchain install 1.97.1 --profile minimal --component rustfmt,clippy
pnpm smoke
```

`pnpm smoke` is the acceptance entry point. It uses frozen installs in both npm workspaces, explicit locked SBF/IDL builds, generated-code verification, type checks, ABI tests, installed dependency traversal, and a new offline Surfpool process. It deploys the built binary using standard RPC and a real signed Solana deployment. Signature and blockhash validation remain enabled. No account injection creates a successful probe.

Default RPC/WS ports are 18899/18900; override `RIVALT_RPC_PORT`/`RIVALT_WS_PORT` if needed. Occupied ports cause failure. The supervisor creates a UTC run directory and traps exit to stop only its own Surfpool PID. It does not use the user's default Solana wallet. The deterministic keys generated by `ops/local-keys.mjs` are public local fixtures, restricted to loopback by the harness, with key files ignored by Git. Never fund them on a cluster.

For a clean build, run `cargo clean` before `pnpm smoke`. This removes only this repository's target artifacts. Runtime evidence is stored in `.local/runs/<UTC>-<pid>/`; do not reuse that identity after a chain reset.

Each smoke run records installed versions, executable hashes and the actual SBF compiler identity. Anchor SPL is not yet needed; P02 must use the selected 1.2.1 release when adding custody.

The host already had v1.52 platform tools. Downloading Anchor's default v1.57 failed with ENOSPC; the installed v1.52 lacks the v3 target (`can't find crate for core`), but builds the program on v0. This explicit compatibility choice supersedes reliance on Anchor's target defaults. Binary architecture is distinct from transaction message version (the SDK uses v0 messages).

Anchor 1.2.1 needs different argument forwarding for its binary and IDL commands. `ops/build.sh` uses:

```sh
anchor build --no-idl --tools-version v1.52 --arch v0 -- -- --locked
anchor idl build -p clearing -o packages/sdk/idl/clearing.json -- --locked
```

Disabling host debug symbols/incremental builds limits local disk use. The legacy test workspace does not approve optional native acceleration scripts; its pure JavaScript path is tested. No workspace dependency overrides are used. `ops/check-dependencies.mjs` traverses the actual installed runtime graph and rejects any legacy Anchor or web3.js version.

## Probe ABI

Local program: `Egn8THHpn7AxDMZKgBKui5YTdTcwn2wxwXkFuKzDDbKo`. This address derives from a public test fixture; it is not a devnet or funded deployment identity.

`probe(nonce: u64, signed_value: i128, optional_value: Option<u64>, choice: Empty | Number{value: u64})` initializes one record and emits one `ProbeRecorded` event by Anchor event-CPI. The maximum u64 nonce deliberately rejects with custom error 6000. Account initialization also makes duplicate successful nonces reject.

Account order: owner (writable signer), record (writable), system program (read-only), event authority (read-only), clearing program (read-only). Record PDA seeds are UTF-8 `probe`, owner's 32 bytes and nonce as 8 little-endian bytes. Event authority uses Anchor's `__event_authority` seed. The record contains owner, nonce, signed value, optional value, choice and bump; allocation is 83 bytes including its discriminator. The committed generated IDL is the precise encoding authority.

The generated client accepts Kit instructions/signers. web3.js **3.1.1** directly consumes those instructions and asynchronously signs with its Kit-compatible `Keypair`; no legacy object casting is involved. The separate Anchor process exchanges only JSON strings and bytes. Tests cover zero, values above JavaScript's exact-number limit, full u64/i128 bounds, options, both enum variants, discriminator, PDA, account order and flags. Protocol quantities in evidence are decimal strings.

## RPC contract foundations (G06)

The harness independently fetches raw HTTP JSON-RPC data after application submission, compares the fetched transaction bytes, verifies the Ed25519 signature using Node crypto, and decodes its instruction, account and inner event. Legacy Anchor independently decodes the live account/event too.

It exercises getLatestBlockhash, getBlockHeight, simulateTransaction with signature verification, sendTransaction, getSignatureStatuses through finalized, getTransaction in JSON/base64 with `maxSupportedTransactionVersion: 0`, getAccountInfo, getMultipleAccounts, getProgramAccounts, getVersion, getGenesisHash, and getSignaturesForAddress with multiple pages and exclusive before/until boundaries. Account, program, logs, slot and signature WebSocket subscriptions are acknowledged before submission and must produce notifications. A corrupted signature is rejected.

A two-instruction transaction emits a first probe event and then deliberately fails. Both record accounts remain absent. Its error/history are retained; the indexer must always gate financial projection on transaction success, regardless of emitted logs or inner instructions. The final account list contains only the three successful probe records.

No unsupported method was encountered in this exercised set. Token balance RPC checks require actual custody in P02. SQL projections/checkpoints, disconnect/backfill, history retention across restart, and database rebuilding remain P05; local reported commitments do not prove consensus/fork behavior. Browser wallet signing remains P10. This is fresh P01 evidence, not financial or historical test coverage.
