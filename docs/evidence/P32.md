## Stack-frame repair

The compiler's SBF frame scan rejected `routes::execute_core` at offset 4,344,
248 bytes beyond the 4,096-byte limit (estimated frame 4,800). This was caught
during build; it was not a reported landed runtime crash. The relevant clean
failed build is `8279017`, with raw log
`.local/liquidity-execution/build-20261029T142832Z-7183.log`.

Large decoded curve/request values and financial root construction overlapped in
one handler frame. Moving only quote decoding was insufficient. The successful
`022f52e` repair gives `quote_current` and `maker_roots` separate non-inlined frames,
constructs root values directly into the candidate vector through `root_view_value`,
and avoids intermediate boxed copies on SBF's non-reclaiming heap. Borrowed event
serialization also avoids copying full root/order books. See
[route helpers](../../programs/clearing/src/instructions/maker_liquidity/routes/mod.rs),
[root adapter](../../programs/clearing/src/instructions/account_trading/engine.rs) and
[borrowed event](../../programs/clearing/src/instructions/maker_liquidity/routes/commit.rs).

The Anchor contexts were already boxed. No account layout, zero-copy migration,
financial validation, extra heap or budget increase was needed. Subsequent clean
SBF builds and actual maximum-book execution verify the repair. Earlier sampler
frame/heap/CU failures remain historical in the implementation record; the costly
on-chain sampler is superseded by the separately qualified publisher path.

input coverage and correct aggregation are trusted attestations, not on-chain
proofs. Published funding depth is not guaranteed executable margin-backed liquidity.

remain. The changed profile has an eight-member default proof, not a new 64-member
or production qualification. The PostgreSQL projection is deliberately prototype-only.

operators, production SDK/service/indexer/UI integration; P34 owns final combined
